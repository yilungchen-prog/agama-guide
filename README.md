## 一、核心立場

- 以**原始佛學**（阿含經、巴利尼柯耶）為起點，導向**理性修佛**的態度。
- 判準是「能不能驗證」，所有說法分三層：
  1. 科學可驗證：以「科學怎麼看」框呈現，研究需先查證並寫明限制。
  2. 自己可驗證：本指南的主體（念住、第二支箭等）。
  3. 無法驗證，存而不論：輪迴、來世、神通、福報、地獄果報等，提到時標明「經典這樣說」。
- 不主動延伸大乘、禪宗等後期理論；後期或通俗故事只當引子，並標明出處層級。
- 傳法風格偏向阿姜查森林傳統：免費、不募款、不行銷，讓內容自己說話。
- 不連結外部經文網站（經號只保留純文字）。
- 授權：老陳撰寫的內容採 CC BY 4.0，歡迎自由連結、轉載，註明出處即可（引用他人的文字除外）。

## 四、檔案結構

- `index.html`：程式（版面、目錄、章節切換、名詞小卡、圖解、互動演練、辭典頁、自動更新）
- `manifest.json`、`sw.js`、`icons/`：加入手機主畫面與離線閱讀（網路優先，沒網路時用手機裡存的版本）
- `version.json`：目前版本號；每次發布要和 `index.html` 裡的 `APP_VER` 一起更新，讀者打開網站時會自動重新載入新版
- `content/chapters.json`：章節清單（id、章名、標題、檔案、所屬篇、按鈕名稱 short）
- `content/*.html`：各章內文
- `content/glossary.json`：名詞小卡（term、pali、match、def、see、cat）
- `content/qa.json`：入門問答（cat、q、a）
- `content/books.json`：推薦閱讀（title、author、level、chapters、why、tip）
- `content/diagrams.json`：圖解資料
- `content/drills.json`：互動演練

## 五、常用維護方式

- **新增一章**：在 `content/` 加一個 html，再到 `chapters.json` 加一筆。
- **新增名詞**：在 `glossary.json` 加一筆；`match` 是內文中要自動標示的字。
- **新增問答**：在 `qa.json` 加一筆，答案裡寫「第X章」會自動變成連結。
- **新增推薦書**：在 `books.json` 加一筆，`chapters` 填要出現在哪幾章。
- **意見表單**：`index.html` 的 `FORM_URL` 與 `FORM_CH_ENTRY`（entry.186048612）。
- **PDF**：`python3 tools/build_pdfs.py` 產生 `pdf/<章>.pdf` 與 `pdf/book.pdf`（只重做內容有變的章節；改了版面要加 `--force`）。
- **發布**：先跑 PDF 腳本，再更新 `version.json` 與 `APP_VER`，推送到 GitHub。

## 閱讀小效果（不干擾閱讀）

- 進入章節時，大標題有一道金光掃過一次（`.shine`）。
- 頂端進度條：金色漸層，前端有一個呼吸發光的小點（`#bar::after`）。
- 手機寬度下，小節標題左邊的金線在滑到時由上往下畫出來（IntersectionObserver 加 `.in`）。
- 每章結尾有一朵小蓮花綻開，配「這一章讀完了」（`.done`）。
- 都遵守系統的「減少動態效果」設定；列印與 PDF 不顯示。
- 刻意不做：章節外框繞光、段落浮現（會干擾閱讀）。
